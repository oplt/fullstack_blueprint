1. P0/P1 — CONCRETE RELIABILITY AND SECURITY FIXES
1.1 Atomic rate limiter (P1). backend/core/rate_limit.py:19-36 and :53-61 and backend/api/middleware/public_rate_limit.py:23-34 duplicate Redis INCR then EXPIRE in separate commands. A crash/network interruption between calls can leave a permanent key (TTL -1, never expires) and block a user indefinitely. Implement one atomic Redis Lua operation (or equivalent safe transaction) that increments, sets expiry only when new or TTL missing, and returns count and TTL in one round trip. For example, Lua INCR; TTL; if TTL < 0 then EXPIRE; TTL; return {count,ttl}. Do not reset expiry for every request. Handle TTL race, reject invalid window/max, clamp Retry-After to positive seconds. Reuse shared low-level function in public middleware and auth/AI checks, keep separate namespaced keys and fail policies. :39-61 enforce_rate_limit/increment_rate_limit unconditionally fail open while check_rate_limit respects RATE_LIMIT_FAIL_OPEN; reconcile with core/config.py:513-514 production forbids fail-open. Audit identity router callsites and decide explicit fail-closed for security-sensitive auth/AI, public 503 on Redis outage where configured. Do not leak raw email or sensitive keys in logs (:50,60,68); hash normalized email in auth keys if compatible. Avoid public-IP limits on liveness/readiness probes (current middleware:19 includes /health/). Verify proxy trust config rather than blindly trust forwarded IP. Test concurrency, expiration repair, limit boundaries, fail open/closed, Redis outage, health endpoint, and exact Retry-After. Keep existing rate policies unless documented changes.
1.2 Request size enforcement (P1). backend/api/middleware/request_limits.py:20-29 returns 413 for oversized/malformed Content-Length, but :34-49 chunked overflow returns http.disconnect to app, then never sends 413. App can raise ClientDisconnect or return another status; comments admit no deterministic chunked response. Implement ASGI receive wrapper and controlled response handling that raises dedicated size-limit exception and returns exactly one 413 when no response started; prevent app from consuming over-limit chunks. For endpoints that could send before consuming body, define/document behavior and enforce at proxy too; never emit second response after start. Avoid reading entire large request into memory. Reject negative/malformed/conflicting lengths as appropriate (400 malformed, 413 oversized), count bytes, ensure multipart cleanup/no partial DB/file writes. Ensure security headers, CORS, correlation ID apply to errors by middleware order (api/main.py:85-101). Test exact boundary, chunked overflow without length, invalid/negative length, disconnect, multipart, early response; include real ASGI integration. Do not change upload limit semantics without coordinating RAG config.
1.3 Outbox concurrency and transaction integrity (P1). backend/modules/events/repository.py:23-44 performs select by dedupe_key then insert; unique constraint events/models.py:22,29 means concurrent enqueue can throw IntegrityError and invalidate caller transaction. Use PostgreSQL INSERT ... ON CONFLICT DO NOTHING RETURNING then select existing row (or savepoint with explicit conflict handling); handle event_id vs dedupe_key correctly; reject conflicting identity/payload rather than silently misattribute. :96-112 consumer receipt check-then-insert also races under concurrent callers (unique constraint models.py:53). Claim receipt atomically before transactional handler, roll it back if handler fails; external side effect uses stable event_id idempotency key. Preserve existing transaction ownership.
- events/service.py:37-55 holds a batch transaction and row locks across all handler awaits, then commits once. :40 validates payload outside try; malformed row aborts entire batch. :49-50 marks failure in same transaction even if handler caused SQL error (session may be failed) or made partial DB writes. Add per-event error isolation/savepoint or short claim transaction + per-event transaction/lease. Choose simplest architecture consistent with handler ownership and durable at-least-once semantics. If releasing locks, add claim token/lease owner and conditional status update to prevent stale worker publishing after reclaim. Keep FOR UPDATE SKIP LOCKED (:62), bounded batches, retries, dead letters, stale claim recovery, error redaction, stable ordering; add retry jitter only if justified. Test duplicate enqueue concurrently, malformed payload, handler DB error and rollback, crash/reclaim, receipt race, duplicate external effect idempotency, one bad event does not block others. Avoid introducing another broker; reuse existing infrastructure.
1.4 Configuration consistency / secret handling (P1). backend/modules/settings/service.py:394-447 validates against process-local settings, writes .env and mutates all fields on global settings object in a thread. This cannot update other API workers or Celery processes, already-created DB/Redis clients, router registration, or cached configs; concurrent updates validate stale snapshots. EnvFileStore has file lock and atomic replace (env_file_store.py:23-29,56-69), but does not make the entire validation/read/merge/runtime mutation atomic. :415-422 accepts unknown keys into raw_updates and only validates known values; :427 exposes str(Pydantic error) which may contain secret input. Prefer immutable deployment config from env + restart, separate DB-backed allowlisted runtime feature flags from infrastructure credentials. Make env editor dev-only/read-only in production or remove entirely if no real requirement; expose only safe metadata, reject unknown keys, do not allow arbitrary dotenv key/value injection (newline/quotes, escaping). If retaining editor for local development, lock complete read/validate/write and restrict editable keys, secure permissions, return sanitized field error without raw input, indicate restart required, don't mutate global live infrastructure settings. Preserve redaction sentinel semantics, do not print secret values. Test concurrent updates, rejected unknown/secret keys, invalid input, restart behavior, file permissions, production restrictions and multiworker consistency. Coordinate UI AdminSettings with frontend; update routes/schema/docs if removing editor. Never return real credentials.
1.5 CORS and middleware order. backend/api/main.py:85-101 registers several BaseHTTPMiddleware; actual outer-to-inner order is reverse. :95-96 allowed headers only Content-Type and configured CSRF. frontend streaming.ts:67-69 sends Last-Event-ID when reconnecting; other API key/idempotency/correlation/authorization headers may be required by actual public endpoints. Enumerate actual required headers from routes/API contract; allow only those (including Last-Event-ID if resumable SSE supported), HEAD if needed, expose required correlation/Retry-After if clients read them, keep explicit origins and credentials. Ensure correlation context, logging/security headers and CORS wrap early 403/413/429 responses as intended. Prefer pure ASGI middleware where necessary for streaming/contextvars rather than a large rewrite. Test cross-origin OPTIONS, cookie CSRF, early rejections, streaming, request ID propagation. Do not weaken CSRF or authentication; backend/api/middleware/csrf.py:7-30 exempt paths must match real auth routes and threat model. Preserve constant-time token comparison as appropriate and secure cookie posture. Audit actual endpoint paths, not speculative changes.
1.6 Session rotation and bulk session revocation. identity_access/repository.py:52-56 ALREADY uses FOR UPDATE; identity_access/service.py:112-136 already revokes and replaces refresh atomically within transaction. Do not mislabel as missing lock or remove it. Test simultaneous refresh across tabs (one wins, other safely fails; coordinate frontend). :62-66 revokes all active sessions by loading each and mutating rows. Replace with one SQL UPDATE with same user/non-revoked/not-expired semantics (check whether expired rows should also be revoked), transaction-owned flush, correct in-memory/session semantics. Preserve password reset/session revocation behavior. Ensure auth API error messages don't leak accounts; confirm regression tests before changes.
1.7 Agent/RAG job state races (verify, not proven). backend/modules/rag/application/document_ingestion_service.py:227-255 enqueue, :264-452 indexing with multiple commits; backend/modules/rag/infrastructure/repositories.py:800-842 get_active/update_ingestion_job; backend/modules/ai/agent_workflow_service.py:102-192 start/approve/resume/cancel and :195-282 execute. Check idempotent transition guards, uniqueness/locking for one active job per document, concurrent resume/cancel, worker retries, external calls after commit, orphaned file cleanup and failure status. Do not assume multiple commits automatically wrong (may intentionally expose progress). Add race tests and conditional state transitions/transactional enqueue where missing. Use existing outbox if it actually fits, not new queue technology. Preserve citation revisions, ACL and retry safety.
