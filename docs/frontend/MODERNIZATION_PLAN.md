## Migration risks and checkpoints

| Risk | Verification or mitigation |
| --- | --- |
| Bundler/plugin/Node incompatibility | Treat Vite, React plugin, Vitest/coverage and PWA as an interdependent set. Exercise `npm ci` on Node 22.13+ and 24 before changing the supported range. Confirm same-origin proxy and output content. |
| CSS reset and stacked overlays | Introduce Tailwind layers in a small slice, inspect legacy pages both themes, and test nested dialogs/menus, restoration, scroll lock and mobile drawer. Keep semantic variables synchronized before removing legacy colors. |
| Quiet UX regression | Preserve user-visible keyboard controls, query-param history, focus, mobile toolbar actions, date/query ranges and table behavior. Regression fixtures follow routes across swaps. |
| Client authorization drift | Compare optional flags and entitlement combinations against backend metadata and direct API authorization. Keep document ownership and project membership checks in services. |
| Contract or session regression | Verify 401 concurrency, 403/422, logout with pending queries, transport replay/abort and cookie names. Export one deterministic generation profile with the full schema surface and test reduced runtime profiles too. |
| Nonexistent AI protocol | Keep live JSON workflows and exercise the event parser only against contracts that exist. Keep unsupported events explicit in fixtures and document required backend work. |
| Risky dependency or PWA removal | Retain a usable incremental state between phases. Remove packages only after source/test/build and lockfile checks establish their consumers are gone. Check precache budget and no sensitive response caching. |

Each phase records actual checks, changes to packages and known failures. If verification reveals a regression, resolve it in the phase that introduced it before depending on the change.
