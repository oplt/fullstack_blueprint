# Frontend architecture

Baseline source revision `3271ffb`. The frontend is a single npm package and a client-rendered Vite SPA. FastAPI is the API and authorization authority. Production hosting serves the build with history fallback and proxies `/api` on the same HTTPS origin.

## State ownership

| State | Owner and existing behavior |
| --- | --- |
| Remote records and identity | TanStack Query caches response data. The auth context derives identity and admin state from the current user query. Defaults are one retry, no refetch on focus and shared timing overrides. Every read query forwards TanStack Query's `AbortSignal` to the credentialed transport. Logout and sign-in cancel/clear the cache at the session boundary, preventing cross-user leakage. |
| Forms | React Hook Form with Zod in auth, profile, projects and AI Studio, alongside local form state in other features. Shared `formControls`, server-error mapping, file upload and multi-step helpers provide consistent boundaries. Pydantic validates independently. |
| Navigation | React Router path params and search params. `app/routes.ts` owns canonical paths and builders; `app/searchParams.ts` validates enum, bounded integer and required-token values. `useTabQueryParam` supports refresh, deep links, aliases and browser history. |
| UI preferences | Color mode context defaults to light and can follow system preference. Drawer and local panels use React state; non-sensitive sidebar collapse and selected-project preferences use localStorage. Auth/session data remains cookie and Query controlled. |
| Workspace state | Component state and feature hooks own local selections. Add a separate store only if a cross-component workflow demonstrably requires one. |

## API flows and authority

- Normal JSON requests send cookies, use `X-CSRF-Token` from the readable CSRF cookie, and retry one 401 after a module-level shared refresh promise. Auth endpoint wrappers can disable this retry. File uploads use FormData and browser-managed boundaries. The transport handles 204 and exposes paginated envelopes or item-only adapters. Read API methods accept `ApiRequestOptions`, and query hooks forward their signal for network cancellation.
- The backend issues HttpOnly access/refresh cookies, rotates them on refresh and checks JWT/session state on protected routes. Unsafe cookie-authenticated requests require the CSRF cookie and matching header outside explicit exemptions. Server routes enforce admins and service-layer resource access, including project roles and RAG document access. Client guards control navigation and rendering.
- Startup settings conditionally register optional routers in `backend/api/router.py`. The AI and agent routers also depend on the enabled AI module in platform configuration. `/platform/metadata` returns available features and enabled modules. Profile/admin settings tabs, route guards and shell use metadata or auth checks at separate sites. Commercial plans and runtime feature flags are separate resources.
- `apiFetchStream` is an unused raw Response helper with cookies and CSRF and no 401 renewal. Existing AI, agent and RAG routes expose JSON and job/status contracts. Source search found no frontend stream reader or public SSE route in those modules. A streaming workspace needs a verified event contract before live integration.
- Phase 10 keeps that boundary explicit: `features/ai/workspace/types.ts` validates stream events, `streaming.ts` handles SSE parsing/cancellation/reconnect, and `useAiWorkspaceStream` consumes an injected connector. `fixtures.ts` is isolated development data and is never used by production routes.
- Phase 11 keeps structured model output explicit: `generative-ui/schemas` and `validation.ts` enforce a closed Zod contract and payload limits, `registry` maps only allowlisted types to fixed renderers, and `actions/actionDispatcher.ts` separates user-confirmed UI intents from backend-authorized execution.
- Backend routing remains within the modular monolith. Routes use request-scoped SQLAlchemy sessions and delegate through services to repositories and adapters. RAG owns ingestion and index revisions, including documents submitted through AI Studio.

## Route and contract inventory

| Surface | Retained functionality | Current API and schema owners |
| --- | --- | --- |
| `/`, `/verify-email`, `/reset-password` | Sign-in, registration including admin invite, MFA challenge, email verification/resend and password recovery. | `api/auth.ts` ↔ identity_access router/schemas. |
| `/dashboard` | Project, notification and account summaries, quick navigation and calendar when enabled. | Projects, users, notifications, platform metadata and calendar. |
| `/projects`, `/projects/:projectId` | List/create/details, task workflow and ordering, editing, assignment and deletion, date/priority/status. Membership routes and role checks already exist in backend. | `api/projects.ts`, user directory ↔ projects/users routers and schemas. |
| `/calendar` | Day/week/month/year views, planner items and associated project tasks, range navigation and item details. | `api/calendar.ts` ↔ calendar router/schemas. |
| `/profile` | Profile/account details, avatar, password change, session list/revocation, MFA setup with QR and verification, notifications/settings navigation. | `api/{profile,users,auth}.ts` ↔ profile, users, identity_access routers/schemas. |
| `/notifications` | Inbox, mark read/all read and per-channel preferences. | `api/notifications.ts` ↔ notifications router/schemas. |
| `/platform`, `/admin/platform` | Plan selection and subscription, feature access, API-key lifecycle, webhooks and test delivery, branding/module packs, plans, feature flags and email templates. | `api/platform.ts` ↔ platform config, billing, API key, webhook, flag and template routes/schemas. |
| `/admin/users`, `/admin/settings` | User search/list and role/status/verification updates, configuration visibility and database-backed setting CRUD. | `api/{admin,settings}.ts` ↔ admin/settings routers and schemas. |
| `/ai` | Provider/prompt library, templates and versions, run playground, documents and retrieval, reviews, feedback, datasets and evaluation runs. | `api/ai.ts` ↔ AI subrouters and schemas. AI document handlers delegate ingestion to RAG. |
| `/agent` | Trigger runs, browse/filter/page history, inspect trace steps, citations, provenance, cost and usage metadata when present. | `api/agent.ts` ↔ AI agent router/schemas. |
| `/rag` | Upload/list/index/delete documents, ingestion status, chunk inspection, retrieval, answers with citations and query history. | `api/rag.ts` ↔ RAG API routes/schemas. Evaluations also appear in AI Studio. |
| `/memory` | Browse/search memories, view details and audit logs, forget/delete with supported scope. | `api/memory.ts` ↔ memory API routes/schemas. |
| `/observability` | Health and integration status, filtered Grafana/Tempo exploration, admin Prometheus entry. | `features/observability/{api,types}.ts` ↔ observability router. |

Phase 7 should cover status 204, UUID/date wire types, nullable vs optional fields, multipart, 422 detail arrays and all conditional routers. Preserve UI constraints, such as query-parameter tab unions, in feature models.
